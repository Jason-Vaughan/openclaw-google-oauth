# Learnings — core

**Reading a rule is not applying it.** For any rule below that bears on the decision in front of you, name the rule and say what it changes about that decision — or say that it does not apply, which is also an answer.

- **`openclaw plugins build` regenerates `openclaw.plugin.json`'s `description` field from `src/index.ts`'s `defineToolPlugin` description, unconditionally.** This repo deliberately keeps a different, curated ClawHub-listing description in `package.json`/`openclaw.plugin.json` than the dev-facing one in `src/index.ts` (decided in CHANGELOG v0.3.3). Every time `npm run plugin:build` runs, it silently reverts `openclaw.plugin.json`'s description to the `src/index.ts` text — re-diff and restore the curated copy afterward, don't assume the regenerated file is correct as-is. `openclaw plugins validate` will always report the manifest as "stale" when these two deliberately differ; that's expected, not a bug to chase.
- **This repo's only pre-2026-10-25 CI workflow was tag-triggered (`publish-clawhub.yml`), so `npm test` never ran before a PR merged.** A real `src/skills.test.ts` regression (the v0.4.0 SKILL.md rewrite pushed the "never narrate" rule past the test's first-1500-char check) sat undetected on `main` for months as a result. `.github/workflows/test.yml` now runs `npm ci && npm run build && npm test` on every PR/push to `main` — trust it, but if it's ever missing/disabled again, don't assume a green PR means the test suite passed.
